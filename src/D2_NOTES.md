# D2 の実装メモ

- PRO リファレンスマニュアル §7.1.4.32 では、`GetActiveFileType` の戻り値を 0（開いているファイルなし）、1（NR-500 のノーマル・ロギング用）、2（NR-600 のノーマル・ロギング用）、3（NR-600 の多チャンネルリンク用）と定義している。
- 接続の確立時に `OpenFile` が成功した直後、`GetActiveFileType` を一度読み、得られた非 0 の型をそのセッションの基準値にする。読み取り失敗または型 0 の場合も接続の確立は続け、そのセッションの事前確認は `GetState` のみで行う。確立ログには `file_type_baseline` を記録し、ファイル確認が無効なら `null` とする。`api_returns` には取得した `GetActiveFileType` の値または `GetActiveFileType_error` の詳細を残す。
- 基準値があり `GetState` が正常に読めた場合は、アクティブなファイル型を確認する。基準値と一致すれば正常とする。型 0 のときだけ、設定済みのパスを `OpenFile` に一度渡す。戻り値が 0 で、再取得した型が基準値と一致すれば回復成功とする。ファイル確認に成功した場合は先に読んだ状態を返し、締切判定にはファイル確認の完了時刻を使う。
- 別の非 0 型がアクティブな場合や開き直しに失敗した場合は `Problem` を返し、scheduler がその回を見送る。事前確認中のファイル型の読み取りエラーは `GetState` の取得エラーと同じ扱いとし、切断を検出した場合は既存の再接続経路に乗る。事前確認を通過した後の閉鎖は `Start` のエラーとして記録される。
- ファイル確認を行った場合、事前確認ログの `file_type` に最初に読んだ型を、`file_type_baseline` に基準値を記録する。開き直した場合は `reopen_success` に成否を記録し、取得できた `open_file_retval` と `file_type_after_reopen` も残す。
